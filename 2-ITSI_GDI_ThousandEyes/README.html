ITSI — GDI — ThousandEyes Integration Guide

Purpose: This guide explains how to ingest ThousandEyes data into Splunk ITSI using the Cisco ThousandEyes App for Splunk.

Overview

This document covers the end-to-end setup for integrating Cisco ThousandEyes with Splunk ITSI via the official Splunk App. Once configured, ThousandEyes test metrics, path visualization data, events, and activity logs will be available inside ITSI for episode management and service health monitoring.

Components Involved

Component Description
Cisco ThousandEyes App for Splunk Collects metrics via OpenTelemetry (OTel) and the ThousandEyes REST API
Splunk HEC (HTTP Event Collector) Receives ThousandEyes alert/webhook payloads
Splunk ITSI Consumes events for episode management via the Universal Alerting schema

📖 Official documentation: ThousandEyes Splunk App Integration Guide

Architecture

ThousandEyes data reaches Splunk via two complementary paths:

  1. Cisco ThousandEyes App for Splunk — Uses OpenTelemetry (OTel) streams and the ThousandEyes REST API to collect test metrics, path visualization data, events, and activity logs.
  2. Webhook / Alert Forwarding — ThousandEyes alert notifications are pushed to Splunk HEC and consumed by the ITSI Universal Alerting schema for episode management.

⚠️ Pre-requisite: HEC must have a valid (non-self-signed) TLS certificate.

ThousandEyes  ──[OTel / REST API]──►  Cisco TE App for Splunk  ──►  te_index  ──►  ITSI
ThousandEyes  ──[Webhook / HEC]────►  Splunk HEC               ──►  ITSI Universal Alerting
